# Підключення спільного сховища ДКВС

`index.html` використовує Supabase Auth для входу та таблиці `dkvs_profiles` і `dkvs_records` для спільних записів. Publishable key у браузерному коді є публічним; доступ обмежують RLS-політики з `supabase-schema.sql`.

## Перший запуск

1. Запустіть актуальний `supabase-schema.sql` у Supabase → SQL Editor. Схема безпечно оновлюється повторним запуском. Нові реєстрації потребують одноразового коду-запрошення. Кожен новий код закріплюється за конкретним Nickname для входу. Правильний код одразу активує акаунт зі стандартною роллю «Співробітник».
2. У Supabase відкрийте Authentication → Providers → Email і вимкніть підтвердження email. Для входу сайт використовує ім’я та пароль, а не адресу пошти.
3. Якщо власника ще немає, створіть стартовий одноразовий код у SQL Editor:

```sql
insert into public.dkvs_invites default values returning code;
```

4. Зареєструйте власника на сайті з цим кодом і створіть його обліковий запис.
5. Призначте акаунту власника роль через SQL Editor (код уже активував його під час реєстрації). Замініть ім’я на точний NickName:

```sql
update public.dkvs_profiles
set role = 'Власник сайту'
where lower(login_name) = lower('Дмитро Яворський');
```

6. Після входу власник у розділі «Ролі та доступи» спершу вводить Nickname для входу працівника, а потім створює код. Цей код прийме лише реєстрація з указаним Nickname, і використати його можна один раз.
7. Додайте адресу GitHub Pages у Supabase → Authentication → URL Configuration → Redirect URLs і задайте її як Site URL.

Лише активні акаунти можуть читати спільні записи. Лідер, заступник, слідкуючий або власник можуть створювати оголошення. Ролі також перевіряються базою даних. Видалення акаунта вимикає профіль; повторна реєстрація з тим самим ім’ям після використання нового коду створює активний профіль співробітника.

Відео чорного списку завантажуються у приватне сховище. Інші прикріплені зображення зберігаються в записах як дані зображень.


## Сповіщення про коди в Telegram

Коли власник створює одноразовий код, сайт може надіслати його у приватний чат із Telegram-ботом. Функція `supabase/functions/send-invite-telegram/index.ts` перевіряє, що виклик зробив активний власник; токен бота зберігається лише в Edge Function Secrets.

1. Створіть бота через `@BotFather`, відкрийте приватний чат із ним і натисніть **Start**.
2. Дізнайтеся свій Telegram chat ID (наприклад, через `@userinfobot`).
3. У Supabase → **Edge Functions → Secrets** додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID`. Не додавайте токен до HTML, JavaScript чи GitHub.
4. У Supabase → **Edge Functions** створіть функцію `send-invite-telegram` через **Via Editor**, вставте код із [файлу функції в GitHub](https://github.com/DmitryYavorskyi/dkvs/blob/main/supabase/functions/send-invite-telegram/index.ts) і натисніть **Deploy function**.

Після розгортання створення коду на сайті покаже його на сторінці та надішле повідомлення в Telegram. Якщо Telegram ще не налаштований або недоступний, код залишиться видимим на сторінці.


## Оновлення для кодів, закріплених за Nickname

Застосуйте файл `supabase-invite-binding.sql` у Supabase → SQL Editor. Він додає прив’язку до Nickname і оновлює серверну перевірку. Після цього розгорніть оновлений код Edge Function `send-invite-telegram` із репозиторію, щоб у Telegram-повідомленні також відображався Nickname.
