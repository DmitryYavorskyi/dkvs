# Підключення спільного сховища ДКВС

`index.html` використовує Supabase Auth для входу та таблиці `dkvs_profiles` і `dkvs_records` для спільних записів. Publishable key у браузерному коді є публічним; доступ обмежують RLS-політики з `supabase-schema.sql`.

## Перший запуск

1. Запустіть актуальний `supabase-schema.sql` у Supabase → SQL Editor. Нові акаунти за замовчуванням створюються неактивними; це не дозволяє відвідувачам сторінки отримати доступ до записів.
2. У Supabase відкрийте Authentication → Providers → Email і вимкніть підтвердження email. Для входу сайт використовує ім’я та пароль, а не адресу пошти.
3. На сайті створіть акаунт власника, наприклад `Дмитро Яворський`.
4. Після створення акаунта активуйте його й призначте роль власника через SQL Editor. Замініть ім’я на точний NickName:

```sql
update public.dkvs_profiles
set active = true, role = 'Власник сайту'
where lower(login_name) = lower('Дмитро Яворський');
```

5. Для кожного наступного працівника спочатку попросіть його створити акаунт, потім активуйте профіль у SQL Editor:

```sql
update public.dkvs_profiles
set active = true
where lower(login_name) = lower('NickName працівника');
```

6. Додайте адресу GitHub Pages у Supabase → Authentication → URL Configuration → Redirect URLs і задайте її як Site URL.

Лише активні акаунти можуть читати спільні записи. Лідер, заступник, слідкуючий або власник можуть створювати оголошення. Ролі також перевіряються базою даних. Видалення акаунта вимикає профіль; повторна реєстрація з тим самим ім’ям створює новий неактивний профіль.

Відео чорного списку завантажуються у приватне сховище. Інші прикріплені зображення зберігаються в записах як дані зображень.
